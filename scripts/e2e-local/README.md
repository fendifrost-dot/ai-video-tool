# Local browser run — the real app against a stand-in backend

The live app can only be driven from a signed-in browser, and a browser window that is not on screen will not load
video or audio at all (Chrome defers media in a tab that has never been shown). So the storyboard, the full-screen
shot and Review are also run here: the **real app** (`vite dev`, unmodified) in Chromium, talking to
`fake_backend.py` — a small in-memory stand-in for PostgREST, auth and storage — on a **YSL-shaped** project built
by the app's own box code (`mkfixtures.ts`): 43 shots on the real board's cut points, one 190 s take that starts
0.85 s after the song, an AI clip, an AI image and a B-roll clip. The media is generated by ffmpeg with the time
burned into every frame. None of it is the user's data, and nothing here talks to the real backend.

```
bash scripts/e2e-local/make_media.sh               # once (needs ffmpeg)
npx tsx scripts/e2e-local/mkfixtures.ts            # whenever the box code changes
bash scripts/e2e-local/start.sh                    # backend :54399, app :5200
python3 scripts/e2e-local/run_storyboard.py        # PASS / FAIL, result.json, screenshots
bash scripts/e2e-local/stop.sh                     # as its own command
```

Needs `pip install playwright` and a Chromium (`CHROME_PATH=/path/to/chrome` to use an installed one).

What it checks: the board renders 43 shots with the right media on each; the full-screen shot plays the take's
range for that shot; next / back / full screen; footage assigned from the picker lands on its shot; Review played
against the song shows the right shot at every sample and keeps each video within 0.1 s of the song clock, holds
the take's first frame before the take starts and its last frame after it ends; at phone size nothing overflows,
the shell does not cover the full-screen shot, swiping moves between shots, and the fill-the-screen mode covers the
viewport where the browser has no full screen.

The stand-in understands `eq / neq / is / in / not.* / order / limit`, inserts, upserts (`on_conflict`), updates and
deletes, single-object requests, signed storage links with range requests, and returns `[]` for tables it has no
fixtures for. Edge functions answer `{ ok: true }` — generation is not exercised here.
