# Local browser run — the real app against a stand-in backend

The live app can only be driven from a signed-in browser, and a browser window that is not on screen will not load
video or audio at all (Chrome defers media in a tab that has never been shown). So the storyboard, the full-screen
shot and Review are also run here: the **real app** (`vite dev`, unmodified) in Chromium, talking to
`fake_backend.py` — a small in-memory stand-in for PostgREST, auth and storage — on a **YSL-shaped** project built
by the app's own box code (`mkfixtures.ts`): 43 shots on the real board's cut points, one 190 s take that starts
0.85 s after the song, an AI clip, an AI image and a B-roll clip — plus a second project that has only a song and
plain lyrics. The media is generated by ffmpeg with the time burned into every frame: the take and the AI clip are
VP9 in MP4 (a stock Chromium plays it, and Review's "Check this cut" reads its index and decodes its frames), the
B-roll is WebM, and the song is a rising tone, so any window of it says where in the song it was cut from. None of it is the user's data, and nothing here talks to the real backend.

```
bash scripts/e2e-local/make_media.sh               # once (needs ffmpeg)
npx tsx scripts/e2e-local/mkfixtures.ts            # whenever the box code changes
bash scripts/e2e-local/start.sh                    # backend :54399, app :5200
python3 scripts/e2e-local/run_storyboard.py        # PASS / FAIL, result.json, screenshots
bash scripts/e2e-local/stop.sh                     # as its own command
```

Needs `pip install playwright` and a Chromium (`CHROME_PATH=/path/to/chrome` to use an installed one).

What it checks: the board renders 43 shots with the right media on each; the full-screen shot plays the take's
range for that shot; next / back / full screen; footage assigned from the picker lands on its shot; Review played
against the song shows the right shot at every sample and keeps each video within 0.1 s of the song clock, holds
the take's first frame before the take starts and its last frame after it ends; **Check this cut** passes every
line on the real files (song and every file open and decode, the cut run against the song clock, the player's
links, and the player itself read back at 24 moments); the **project frame** is 9:16 by default and Review and the
full-screen shot follow it when Setup changes it to 16:9; **lyric timing** in Setup — on the project that already
has timed lines it is run again, compared with the saved timing and discarded, and on the project with plain lyrics
only it is run and saved; at phone size nothing overflows, the shell does not cover the full-screen shot, swiping
moves between shots, the fill-the-screen mode covers the viewport where the browser has no full screen, and the
**Voice Director** is a button that opens to a sheet and closes back to the button (expanded on desktop). And, from
the post-production-test hardening: a shot's **timed beats** on the card, in the full-screen shot and its editor (one
hung on a sung line sits where the line is sung; one that switches to a lighting state says that state's words and
keeps the pointer), the edit's **effect** on the picture in Review on the song clock, **continuity entities** (the
shot's place and light, the project's entities with the shots that use them, the place's approved picture as what a
restaging uses), **treatment versions** (an edit keeps what it replaced; a version is restored), Export's **render
contract**, **video variations** (a new one has its own treatment, an empty board and no entities while the first is
untouched; a duplicate carries the shots and their footage under new ids; the page chip names the one being worked in),
and that a page with an unfinished job **asks the server** to move it and polls no provider itself.

The stand-in understands `eq / neq / is / in / not.* / order / limit`, inserts, upserts (`on_conflict`), updates and
deletes, single-object requests, signed storage links with range requests, and returns `[]` for tables it has no
fixtures for. It also does what the database's treatment-history trigger does (an update that changes a project's
treatment or its notes keeps the replaced one in `treatment_versions`), and answers `provider-jobs-tick` with "nothing
to move". `lyric-align-proxy` is answered by a stand-in transcriber that reads the window's place in the song
from its tone and "hears" the fixture's lyric lines inside it; every other edge function answers `{ ok: true }` —
generation is not exercised here.
