## 1 · What was run

Not the route the protocol named. `world-still-proxy` still has no credential on any machine
reachable from a cloud session, so the experiment ran against **Runway `gen-4` text-to-image through
the Runway MCP connector** — a real image model, reached directly, on credits already held.

Both arms: same model, same ratio (832:1104), same session. Only the prompt differs, and the
treatment arm came from `applyRealism` (`realism_arms.mts`, `realismVersion 1`), not retyped.

**n = 6 per arm**, against the protocol's 41. A pilot.

## 2 · The numbers, and why the first half of this run was a trap

| endpoint | role | control | treatment | change | p |
|---|---|---|---|---|---|
| `detail_mf_norm` | **PRIMARY** | 694.9 | 602.4 | **−13%** | **0.87** |
| `noise_hf` | secondary | 2.79 | 3.28 | +18% | 0.68 |
| `sat_mean` | **GUARD** | 111.7 | 107.8 | −3% | 0.71 |

`droppedNoFace`: 0 in both arms. The guard is clean — the modifier did not re-grade the picture.

**At n = 4 the primary read +121%. At n = 6 it reads −13%.** Same experiment, same prompts, two more
samples per arm, and the effect reversed sign. Nothing changed except the sample.

This is the single most useful thing the run produced. A 121% difference in the predicted direction
is exactly the shape of a result someone reports as promising; it was noise, and four more images
were enough to erase it. Any claim built on the n = 4 half of this run would have been false.

**No effect was measured, and none is claimed.**

## 3 · The modifier pulls the generation off the prompt

`ab_contact_sheet.jpg`. The treatment arm drifted off the base prompt's composition:

* **`treatment_000`** and **`treatment_004`** — full-length figures in traditional dress, head to toe.
  The base prompt says **waist-up framing**.
* **`treatment_001`** — the face is covered to the eyes by a turtleneck. A face-texture experiment
  that produced almost no visible face, and it still scored.

The control arm held the brief in all six.

The modifier appends ~800 characters to a 115-character prompt — **8:1** — and on this model that
displaced the instruction that came first. **No pre-registered endpoint measures composition
adherence**, so the experiment was blind to the one effect it demonstrated. That is a cost the
modifier may be imposing wherever it is switched on.

## 4 · Casting: the default is wrong for this project

Counted across all 12 images from the prompt "**A person** standing in a doorway…":

| | count |
|---|---|
| East Asian | 8 |
| South Asian | 2 |
| **Black** | **2** |

This is a **rap video**. The artist is Black, and the cast should reflect that. An unspecified
"a person" hands casting to the model's prior, and on `gen-4` that prior is overwhelmingly East
Asian — 10 of 12 here.

**This is not the realism modifier's job to fix, and it must not become its job.** The modifier is
deliberately subject-neutral: it names no complexion, and `realism.test.ts` enforces that, because a
modifier that dictates who is in frame would silently overrule the director on every shot it touches.

Casting is **approved-treatment authority** — it belongs in the shot description, where a human set
it, and where `compatibility.ts` already ranks it above anything advisory.

**The gap this exposes is real and already documented:** AVT has no cast record. `ENTITY_KINDS` is
`location | prop | lighting`, and `entityFromRow` drops anything else, so there is nowhere to say
"this recurring character is cast like this" once and have every shot inherit it. Every shot has to
re-state casting in prose, or get the model's default. For a project whose whole subject is one
artist and his world, that is the more valuable thing to build than any prompt wording.

## 5 · Honesty notes

* **The visual read was NOT blind.** The connector labels images by arm. `blind_key.json` cannot fix
  that; a blind read needs someone who has not seen the run.
* **A credit figure was reported wrong once.** An earlier version of this document said "96 of 102
  spent, 6 left" after only 8 images had been generated — it subtracted a top-up call the permission
  classifier had **blocked**, which never ran and never billed. The true balance at that point was
  38, as the account showed. The figure above (96 spent, 6 left, 12 images) is the real one.
* **Route provenance was wrong on the first scoring pass**: `ab_result.json` hardcoded
  `world-still-proxy` / `grok-imagine-image-quality`, stamping a Runway run as a Grok one. `--route`
  and `--model` are now required for a `--score-only` run.
* **Negatives remain untested.** The Runway image tool exposes no negative-prompt parameter and Grok
  supports none, yet the 0-of-15 audit gap that justified the modifier is a **negatives** gap.
* **No seed lock.** Six unseeded samples per arm is a weak instrument by construction — as §2 shows.
